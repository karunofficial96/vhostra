# Local Site previews

Dashboard previews, Open Site, and the explicit Check Site action use `SiteUrlResolver` (`electron/site-url.ts`). The resolver reads the canonical virtual host, aliases, configured HTTP/HTTPS ports, HTTPS request state and current runtime availability. Apache, Nginx and OpenLiteSpeed generate an `X-Vhostra-Site` response marker from the exact virtual-host ID; merely returning HTTP 200 does not establish routing identity.

The configured homepage path is preserved; private query/fragment state is omitted from UI/cache URL metadata, and the routing identity is a hash. The canonical hostname is tried first, using HTTPS when requested and available, then HTTP. Only configured, locally mapped aliases can follow. Each candidate is probed with its named Host/SNI over loopback; redirects must remain among mapped local origins, with every hop verifying the same virtual host. No website body is retained by the probe. Missing/conflicting Hosts mappings produce a useful state and an explicit Repair Site action through the existing scoped administrative workflow. Dashboard capture never writes Hosts.

The hidden Chromium window navigates directly to the verified named URL. It does not replace a named hostname with `127.0.0.1` or override Chromium's Host header. The built-in localhost Site alone uses its own localhost URL. Production uses actual OS Hosts resolution; acceptance harnesses use a test-only Chromium hostname resolver rule and temporary Hosts files so tests never modify system mappings.

TLS uses normal verification. The private preview session can additionally accept only the exact Vhostra-managed local certificate, checking its hostname SAN and validity. Node probes verify TLS with that managed certificate as the local trust anchor. There is no global TLS bypass, certificate-error acceptance, or change to default-browser trust. Bad TLS falls back to verified named HTTP when available.

Capture uses a normal 1280×720 first viewport. User-origin temporary CSS suppresses both Chromium scrollbar directions, without disabling overflow, zooming, changing layout breakpoints, imposing the application theme, or writing Site files. DOM readiness and a 500 ms rendering opportunity avoid waiting indefinitely for analytics or continuous connections. The resolver has a six-second deadline, individual connections have a 1.5-second timeout, and capture has a fifteen-second overall deadline. Leaving Dashboard or hiding/minimizing the application cancels active work. Every path destroys the capture window and removes request/certificate/download/permission handlers, timers and storage/connections.

One memory-only Electron session is reused to avoid creating an accumulating set of session partitions; it retains no screenshot renderer. Captures run sequentially, with at most six admitted requests and per-Site deduplication. There is no preview polling, permanent preview window or background refresh scan. Visible, healthy Dashboard entry/visibility events check the local cache; valid entries return without a renderer, while only missing/stale entries generate a preview. The memory session clears its hostname resolver cache before navigation so repaired mappings do not inherit stale DNS state. Manual Refresh Preview affects one Site.

JPEGs are host-side Vhostra cache data: 960×540, quality 75, one stable `<Site ID>.jpg` file, capped at 1 MiB and written atomically with private permissions. Metadata records the rendered Preview URL origin/path (query and fragment state are omitted to protect credentials) and the routing/root/protocol/port identity. Legacy unverified previews are not displayed. Root/hostname/protocol/port changes and removal of the used alias invalidate obsolete owned cache files. Adding an unused alias, changing PHP or changing the web server preserves valid cache metadata. Failed refreshes retain a previous verified screenshot. Concurrent Site/routing changes discard the new capture.

Cards use DESIGN.md surfaces, 16:9 thumbnails and 36 px pill actions. Failures show simple text, an optional collapsed Show details disclosure with sanitized diagnostics, and Repair Site where applicable. Preview URL values are selectable; labels, summaries, headings and controls remain unselectable.

## Diagnosis and acceptance (2026-09-29)

The previous implementation explicitly changed `site.url.hostname` to `127.0.0.1` before `loadURL`, redirected named subresources to the same bare address, and overwrote the Host header. This bypassed Hosts state and could conceal incorrect virtual-host routing. An isolated reproduction confirmed that exact legacy navigation path, but **the reported `ERR_INVALID_ARGUMENT` did not recur on the installed Electron build**. It is not claimed as a reproduced error or assigned an unproven Chromium cause. The problematic URL rewriting/header override path has been removed, and real named navigation is tested.

Actual acceptance also exposed two serving defects: Nginx's first generated named vhost could become the default, and Apache's unconditional PHP proxy could make a nonexistent `index.php` shadow an existing `index.html`. Localhost is now the explicit Nginx default/first Apache vhost. Apache forwards existing PHP entry points with a file-conditioned proxy rewrite, preserving PHP-first index priority and permitting static index fallback. These changes affect generated managed configuration only.

All screenshot/probe requests and cache stay local. Nonlocal HTTP(S), websocket origins and unsupported schemes are blocked in the capture session; downloads/windows/permissions and JavaScript dialogs are denied. No remote screenshot service, upload endpoint, telemetry, identifier or dependency was added. The local request policy intentionally blocks third-party page resources, preserving the previous privacy boundary. Public update checks and explicit user browser openings retain their separate existing behavior.

All three listeners/PHP/phpMyAdmin/permalinks, TLS-port conflict ownership, PHP 8.3→8.4 promotion with database preservation, cwebp/cache controls, injected promotion rollback and stopped-state switching passed. Only isolated test resources were removed.

Existing running services with older generated configuration need Repair Site or Restart Services once to install the routing marker. Missing markers fail safely and offer Repair; Dashboard does not silently restart services or modify Hosts just to produce an image. Native UI acceptance additionally verifies that rebuild transitions retain the previous thumbnail and that Dashboard cache checks regenerate a deleted host JPEG even when Chromium has an older image cached.

Runtime transitions to healthy clear only the bounded automatic failure history. This permits immediate recovery after a rebuild/start while retaining valid cached images; it adds no retry timer or permanent renderer. The native IPC harness verifies a previously failing Site captures immediately with `force=false` after that transition.
