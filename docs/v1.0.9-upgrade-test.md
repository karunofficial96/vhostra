# Vhostra v1.0.9 physical upgrade test

Run this on a disposable or backed-up system with the published v1.0.8 installed. Record the OS, architecture, installer type, v1.0.8 installer checksum, v1.0.9 candidate checksum, and GitHub Actions run and commit. Keep the published v1.0.8 release unchanged.

1. In v1.0.8, record the Local Configuration Path, application settings, startup preferences, Site definitions and document roots, representative website file hashes, MariaDB database and table names with representative row counts, and Docker containers, mounts, and volumes. Export a full Vhostra backup and independently copy external website roots. Stop Vhostra services before making a cold copy of the managed data directory. Keep all backups outside the installation directory.
2. Quit v1.0.8. Install the matching v1.0.9 candidate on the same account and architecture: replace only `Vhostra.app` on macOS, run the NSIS installer on Windows, upgrade the existing DEB with `apt` on Debian-based systems, or upgrade the existing RPM with `dnf` on RPM-based systems. For AppImage, retain the existing file until the new image is verified, then launch the new image from its intended stable path. Do not invoke Reset or remove Docker volumes.
3. Open v1.0.9. Confirm About shows `1.0.9` and Check for Updates reports up to date when the stable release is published. Before publication, use the automated mock release tests for this check. Verify the Local Configuration Path and each recorded setting and Site definition. Compare representative website file hashes.
4. Start managed services. Confirm each recorded MariaDB database, table, and representative row count remains intact. Compare the Docker mount sources and any separately managed volume IDs with the baseline; confirm no volume or host data path was removed. Check the CLI points to the upgraded application.
5. Restart the app and the OS, then repeat the settings, Sites, website files, MariaDB, and Docker checks. Record exact differences and redacted logs. Treat any loss, reset, unexpected new profile, or wrong installer suggestion as a release blocker.

The update checker only provides download links. It never installs an update. The package scripts and source review do not replace this physical upgrade test, especially for RPM and AppImage installations.
